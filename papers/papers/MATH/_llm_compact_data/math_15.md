# definitions(id|symbol|name|definition|unit|shannon_parallel)
D1|op|Operation|Irreducible unit of processing. One transformation by one processor. Countable, abstractly fungible across domains. Duration varies by substrate|count|bit
D2|Hp(x\|p,g,c)|Processing entropy|Number of ops processor p requires to reduce element x to actionable One for goal g in context c. When 0, element is at Zero-absent. Directly measurable by counting ops in reduction chain|ops|H = −Σ p(x) log p(x)
D3|R*(x,g)|Optimal reduction|Minimum correct op count for any competent processor. Theoretical lower bound on Hp. Isolated-regime quantity|ops|Source entropy rate
D4|N|Time budget|Maximum duration available for processing. Determined by domain physics. Unmanageable (Zero-external). The wall|seconds|Channel bandwidth
D5|d̄|Average op duration|Mean time consumed by one op for a given processor in a given domain|seconds/op|Bit transmission time
D6|N/d̄|Processing capacity|Maximum ops that fit in time budget. Processing analog of Shannon's channel capacity C|ops/period|Channel capacity C
D7|Σ ops(xᵢ)|Processing demand|Total ops required across all active elements (at Infinity or One) at time t|ops/period|Data rate
D8|N/(d̄×H̄p)|Throughput|Units completed per time period. Increases as average Hp decreases through dissolution|units/period|Effective data throughput
D9|−dHp/dt|Dissolution rate|Rate of op count decrease for given element through practice. Varies by element, processor, conditions|ops/repetition|Decoder adaptation rate
D10|in situ − isolated|Concurrency tax|Additional ops generated by execution environment: contention, cascade, coordination, blocking, interleave|ops|—

# principles(id|principle|rationale)
P1|The op completes the measurement apparatus|Processing entropy becomes measurable quantity — number you can observe, record, compare across processors, track over time, engineer against
P2|Fundamental inequality: total ops × d̄ ≤ N|When left exceeds right, processor fails. Nature of failure depends on domain but mechanism identical in every case
P3|Op is abstractly fungible like bit is abstractly fungible|Bit over fiber in nanosecond and bit by postal mail in three days are same bit. Mirror-glance op and strategic-planning op are same op. Duration determines how many fit in budget, not nature of op
P4|Hp = op count in reduction chain|Not abstract quantity requiring special formula. If physician executes 14 ops to diagnose, Hp = 14. If experienced physician has dissolved chain, Hp = 0. Directly observable
P5|Every intervention is strategy for keeping left side of inequality smaller than right|Dissolution shrinks ops. Correct classification stops wasting ops on immovable things. Optimal reduction stops at R*. None can increase right side. Time budget is the wall
P6|You cannot make the CPU faster but you can ask it to do fewer things|Performance optimization is decreasing H̄p, not increasing d̄. Universal across all domains
P7|Every recruited system is an op generator|Recruited system adds its entire processing chain, not one op. Minimum systems recruited = proxy for minimum total cost

# dissolution_measurement(id|claim|mechanism)
DM1|Dissolution is measurable reduction of op count toward zero over time|New driver mirror check: 6 ops (week 1) → 2 ops (6 months) → 0 ops (5 years). Count decreases, not qualitative "getting better"
DM2|Dissolution curve: op count per unit plotted over repetitions|Starts high, decreases with practice, approaches zero asymptotically. Shape is empirical question. Trajectory existence is structural property
DM3|R* is minimum ops any competent processor needs for reliable execution|Mirror check R* ≈ 1 op (single glance acquiring image + threat assessment). Below R* = operating blind. Above R* = measurable inefficiency
DM4|Gap between current count and R* = measurable inefficiency. Gap between R* and zero = what dissolution can absorb|Distance from minimum-competent to fully structural
DM5|Dissolution infrastructure bridges the gap before natural dissolution completes|Checklist, jig, IDE autocomplete, recipe, lane departure warning. Lowers Hp externally for processors whose natural dissolution hasn't reached zero

# throughput(id|claim|mechanism)
TH1|Throughput = N / (d̄ × H̄p)|As dissolution progresses, H̄p decreases. Same capacity services more units. Throughput rises not because processor is faster but because it asks less per unit
TH2|Novice surgeon 40 ops/step, expert 4 ops/step = 10× throughput on same pipeline|Not 10× faster per op. 10× fewer ops per unit. Same pipeline, same clock, same budget
TH3|Caching is dissolution|Chain ran once, result stored, now retrieved structurally. Hp drops to zero for cached elements

# decode_legend
fundamental_unit: op = one irreducible transformation by one processor. Fungible across domains like bit across media
fundamental_inequality: total ops × d̄ ≤ N. Every failure mode reduces to this
counting_regimes: isolated (one task, deterministic, R* lives here) vs in situ (concurrent, stochastic, concurrency tax applies)
cascade_cost: direct ops + Σ recovery(promoted elements) + recruited system ops + blocking
communication_cost: ops(sender encoding) + bits(channel) + ops(receiver decoding). Processing terms usually dominate channel term
throughput: N/(d̄×H̄p). Increases via dissolution (decreasing H̄p), not via faster ops
dissolution_stages: first encounter (max Hp) → early practice → competence (≈R*) → fluency → full dissolution (Hp=0)
computation_special: ops vary 4 orders of magnitude by latency tier. R* = min op count + min weighted cost. Context switch = cache cascade
id_prefixes: D=definition|P=principle|FI=failure_inequality|DM=dissolution_measurement|CC=cascade_component|CX=cascade_example|CR=counting_regime|CT=concurrency_tax|DM_*=domain_measurement|SR=system_recruitment|CM=communication|CS=communication_scenario|CW=computation_weight|DT=dissolution_trajectory|DI=dissolution_infrastructure|TH=throughput|OP=open_problem
shannon_bridge: Shannon counts bits on channels. This framework counts ops at endpoints. Total cost = ops + bits + ops. Shannon solved the middle term. This framework solves the outer terms
