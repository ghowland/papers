# principles(id|principle|rationale)
P1|Every statement is falsifiable|Each claim commits to something specific with an observable failure condition. Prerequisite for everything in the paper
P2|Commitment enables platform|A platform is something you build on. Building requires commitment. Commitment requires accepting it might be wrong. Fields that won't commit can't build platforms
P3|Every domain has a completable core|A finite set of infrastructure problems that are bounded, enumerable, buildable, testable, closeable
P4|Tool-generated complexity obscures completable cores|Every tool embodies a formalism that creates questions that only exist because the tool has slots for them. These compound across a field
P5|Data outlives logic|Goals change, logic serving those goals becomes obsolete. Data describes reality not intent and persists across tool transitions
P6|Comprehensive over aggregated|Systems built top-down from the whole maintain consistency. Systems assembled bottom-up trend toward inconsistency and hit a ceiling

# concepts(id|name|definition|category)
K1|General information|Falsifiable claim about reality, independent of observer. Commits to specific state of affairs. Can be tested, can be wrong|epistemology
K2|Contextual data|Observer-dependent state. Describes the person holding it, not the world. Not falsifiable. May change. Depends on mood, context, day|epistemology
K3|Category error|Treating contextual data as general information. Unfalsifiable statement enters decision-making as if testable. Entire structures built on unanchored foundation|anti-pattern
K4|Completable core|Finite set of infrastructure problems every practitioner encounters, every project must solve, solved many times before. Bounded, known requirements|core
K5|Tool-generated complexity|Questions that only exist because a tool's formalism created a slot for them. Real work, skilled practitioners, but unnecessary — generated by tools not problems|anti-pattern
K6|Reference value instability|Committee averages of noisy readings that shift each publication cycle. Results evaluated against shifting ground truth by convention not structural argument|anti-pattern
K7|Platform|Something you build on. Requires commitment to falsifiable position. Holds weight when commitment holds. Failure is located precisely when commitment fails|core
K8|Convergence signal|Extension rate — how often new applications require new substrate primitives. Decreasing = approaching closure. Zero = closed. Not decreasing = wrong design or genuinely incompletable|core
K9|Substrate|Infrastructure embodying unified language. Compiled binary, schema, arithmetic framework. The closeable layer. Contains zero domain knowledge|core
K10|Ongoing layer|Applications, runners, experiments. Tracks human goals and empirical observations which change. Correctly open. Runs on top of closed substrate|core
K11|Passive data substrate|Data layer that answers queries and accepts writes but never invokes work. Passivity prevents orchestrator drift and keeps data layer durable|core
K12|Social resistance|Community structure depends on domain remaining open. Threatens livelihoods, identities, institutions. Manifests as unfalsifiable objections|observation

# method(id|step|name|action|test)
M1|1|Take key results seriously|Identify landmark results community acknowledges but does not follow to structural conclusions. Take as literally true structural constraints|Result typically old, well-tested, broadly accepted in narrow scope but not generalized
M2|2|Unify the language|Replace tool-generated vocabulary with language consistent with key results and falsifiable. Discard distinctions existing only because different tools created them|Unified language must be simpler than field's standard language. If not simpler, tool-generated complexity preserved
M3|3|Implement as substrate|Build infrastructure embodying unified language. Every design decision is a falsifiable commitment|Substrate must match language, language must match key results. Failure visible at specific point
M4|4|Test across domains|Run substrate against multiple application areas within field. Measure extension rate|Rate decreasing = converging. Rate zero = approaching closure. Rate not decreasing = design wrong at identifiable points or domain genuinely incompletable
